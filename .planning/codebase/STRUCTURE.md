# Codebase Structure

**Analysis Date:** 2026-07-21

## Status

This repo is pre-code: there is no `src/`, no package manifest for a portfolio app, and no build tooling for the site itself. The directory layout below reflects the actual current state — design references, content docs, and GSD planning/tooling scaffolding only.

## Directory Purposes

**`Portfolio-Documentation/`:**
- Purpose: Defines what the real portfolio site should say and how it should be structured.
- Contains: Markdown docs (IA, homepage copy, case-study page template). No code.
- Key files: `Portfolio-Documentation/Information Architecture.md` (site map / structure), `Portfolio-Documentation/Homepage Copy V2.md` (copy), `Portfolio-Documentation/Project Page- Template.md` (case-study page structure/copy template).

**`Templates/`:**
- Purpose: Visual/style inspiration only — two full static HTML mockups from other studio/portfolio concepts, each with an accompanying design-rationale markdown file.
- Contains: Self-contained `.html` files (likely inline/embedded CSS given file size ~55KB) and `.md` design specs. Not wired to any build system.
- Key files: `Templates/Noema/Noema Artist Portfolio.html`, `Templates/Noema/Noema Artist Portfolio Design.md`, `Templates/Axisform/Axisform Studio Landing Page.html`, `Templates/Axisform/Axisform Studio Design.md`.
- Note: Do not extend or fork these files as the basis for the real site's codebase — treat as read-only reference material for layout/typography/color/motion decisions.

**`.planning/`:**
- Purpose: GSD workflow state — roadmap, phase plans, and codebase-map documents (including this one).
- Contains: `.planning/codebase/*.md` (generated docs like this one), and (once planning begins) roadmap/phase artifacts.
- Generated: Yes (codebase docs are regenerated by `/gsd-map-codebase`).
- Committed: Yes (planning docs are typically version-controlled in GSD projects).

**`.agents/`, `.claude/`, `.codex/`, `.opencode/`, `.zcode/`:**
- Purpose: GSD tooling configuration for different AI CLI backends (agent definitions, skills, hooks, install state). These support the *planning workflow*, not the portfolio site's runtime.
- Contains: Agent/skill markdown, hook scripts, install-state JSON, per-CLI settings.
- Generated: Partially (install-state and manifest files are tool-generated).
- Committed: Currently untracked per `git status` (`??`) — not yet added to version control as of this analysis.

## Naming Conventions

**Files:**
- Documentation and template files use Title Case with spaces (e.g., `Information Architecture.md`, `Homepage Copy V2.md`, `Axisform Studio Design.md`) rather than kebab-case or snake_case. Future site code will likely need its own convention decided separately (e.g., kebab-case for a JS/TS project), since none of the existing files establish a code-naming precedent.

**Directories:**
- Top-level content directories use descriptive Title/Proper Case names (`Portfolio-Documentation`, `Templates`) rather than lowercase (`docs`, `templates`) — reflects a documentation-first, non-code repo to date.

## Where to Add New Code

When the actual portfolio site build begins, no existing structure dictates placement — this is a decision the first implementation-focused phase should make explicitly. Recommended reference points:

**New site source code:**
- Create a new top-level directory (e.g., `site/` or `app/`, depending on chosen framework) rather than placing code inside `Templates/` or `Portfolio-Documentation/`, both of which are reference-only.

**Content data (case studies, copy):**
- Should ultimately be derived from `Portfolio-Documentation/Project Page- Template.md` (structure) and `Portfolio-Documentation/Homepage Copy V2.md` (copy) — plan to migrate this content into whatever data format the chosen stack uses (MDX, JSON, CMS entries, etc.).

**Design tokens / styling decisions:**
- Should be derived from patterns observed in `Templates/Noema/` and `Templates/Axisform/` (colors, type scale, spacing, motion) — extract values, do not copy the HTML/CSS wholesale.
