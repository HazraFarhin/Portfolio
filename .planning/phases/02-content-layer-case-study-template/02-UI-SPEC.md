**Case-study-specific mapping (locked this phase):**

| Element | Component | `as` | Rationale |
|---------|-----------|------|-----------|
| Case-study page title | `Heading` | `h1` | **Not** `Display` — `Display` is reserved exclusively for the homepage Hero (Phase 3); using it here would blow the above-the-fold budget (see Layout section) |
| One-line summary | `Body` | `p`, `max-w-[62ch]` | Matches Hero's existing summary treatment |
| The 8 body-section titles (Overview, Tools Used, Outcome & Impact, The Challenge, Process, Solution, Learnings & Reflections, Next Project) | `Heading` | `h2` | Large section breaks, consistent with the "cinematic/editorial" direction — repeated at 40px deliberately, not diluted to a smaller ad-hoc size |

| Overview table property names | `Label` | — | Uppercase, tracked, muted — matches existing Label styling |
| Overview table values, all body prose (Challenge/Process/Solution/Learnings paragraphs, list items) | `Body` | — | Standard body reading copy |
| Draft badge text | `Label` | — | Small, quiet status marker |

No 5th font size and no 3rd font weight are introduced anywhere in this phase's UI.

## Case-Study Page Layout & Composition

Literal document order (D-11 — no reordering, no omission):

1. Cover image placeholder (compact banner — see Placeholder Blocks below)
2. Title (`Heading`, `h1`)
3. One-line summary (`Body`)
4. Draft content badge (`DraftBadge`, conditional on `status === 'Draft'`) — directly below title/summary
5. **Overview** (frontmatter-driven grid inside a `Card`) — per D-08/CASE-03, this must be reachable without scrolling
6. Tools Used
7. Outcome & Impact
8. The Challenge (+ optional pull-quote — see UI Considerations)
9. Process (5 fixed sub-stages, 3 with image placeholders)
10. Solution (2 image placeholders + paragraph)
11. Learnings & Reflections
12. Next Project (footer link)

**Composition rule:** each of items 5–11 is a `<section>` wrapping plain flow content (`Heading` + `Body`/`react-markdown` output) directly on the page background — **not** wrapped in a `Card`, except Overview (item 5), which is the one section rendered inside a `Card` (glass) specifically to visually group the skimmable metadata. Wrapping every section in a glass card would read as a stack of boxes and undercut the cinematic/editorial direction; Overview is the deliberate exception because it needs visual containment to read as a distinct "at-a-glance" block.

**Section rhythm:** `py-2xl` (48px) between sections on desktop, `py-xl` (32px) on mobile — spacing tokens only, no new values.

**Above-the-fold budget (resolves the D-08/D-11 tension flagged in 02-RESEARCH.md Pitfall 5):** the combined stack of nav + cover placeholder + title + summary + draft badge + Overview must fit within a typical first viewport without scrolling. This is achieved by three deliberate, load-bearing decisions:
- Cover placeholder height is capped at `clamp(140px, 20vh, 220px)` — a compact banner, never a full-bleed hero image (see Placeholder Blocks).
- Title uses `Heading` (40px), not `Display` (up to 88px) — `Display` stays reserved for the Phase 3 homepage Hero only.
- Overview renders as a single compact `Card` with tight `gap-sm` (8px) row spacing, not a sprawling table.

This target must be visually verified in UAT across a 1440×900 desktop viewport and a 375×812 mobile viewport using the longest actual title/summary text among the 6 placeholder files (see UI Considerations, row 12 — flagged as a backstop check, not a DOM-order assertion).

**Not-found fallback:** composes only existing primitives (`Body` + `Button`), centered on the page, no new component introduced.

### Overview Table Styling

Implemented as a responsive 2-column definition grid (not an HTML `<table>`) inside one `Card` (variant=`glass`):

- **Desktop (≥768px):** `grid grid-cols-[auto_1fr] gap-x-md gap-y-sm` — property column is `Label` (uppercase, tracked, `text-muted-foreground`), value column is `Body` (`text-foreground`).
- **Mobile (<768px):** stacks to a single column — each row becomes `Label` directly above its `Body` value (`gap-y-xs` within a row, `gap-y-sm` between rows).
- **Rows, in template order:** Client, Industry, My Role, Team, Timeline, Links.
- **Links row:** when `external_link` is present, renders two compact `Button` (variant=`ghost`) side by side labeled "Prototype" and "Live Site"; when absent, renders the "Coming soon" copy from the Copywriting Contract instead — never a broken/dead link.

### Draft Content Badge (D-03)

- Component: `DraftBadge`, rendered directly below the title (item 4 in the layout order above), conditional on `status === 'Draft'` (hidden entirely, renders nothing, when `'Published'`).
- Visual: `inline-flex items-center gap-xs rounded-full border border-line bg-secondary/40 px-sm py-xs`, containing `Label`-styled text reading exactly "Draft content — pending final copy".
- **Must not** use `--color-destructive` or any red/warning treatment — this is a quiet, neutral status marker, reusing the same visual register as the existing `metaStatus` Label already shipped in Hero's Card (Phase 1 precedent), never a jarring alert banner.

### Placeholder Image Blocks (D-02)

One shared `ImagePlaceholder` component, props: `{ caption: string; size: 'banner' | 'stage' | 'centerpiece' }`.

- **Visual base (all sizes):** `rounded-2xl border border-line bg-gradient-to-br from-secondary to-dominant flex flex-col items-center justify-center gap-sm` — centered `lucide-react` `ImageOff` icon (`text-muted-foreground`, low emphasis) with a `Label` caption beneath it (e.g. "Cover image — pending", "Research artifact — pending", "Final solution — pending").
- **Sizing per usage** (deliberately tiered, largest → Solution, to preserve the template's own "visual centerpiece" intent even in placeholder form):
  - `banner` (cover image, 1x per page): 21:9 aspect (16:9 on mobile), `max-height: clamp(140px, 20vh, 220px)`.
  - `stage` (Process sub-stage images, 3x per page — Discovery & Research, Ideate & Wireframe, Design & Prototype only; Define and Test & Iterate have no image slot in the authoritative template and must not get one invented): 16:9 aspect, `max-height: 200px`.
  - `centerpiece` (Solution images, 2x per page): 4:3 aspect, `max-height: 360px` — the largest placeholder size on the page.
- Never render a real `<img>` tag against a nonexistent path this phase (react-markdown's `img` tag is remapped unconditionally to `ImagePlaceholder`).

### Process Component (5 Sub-Stages)

- Renders exactly 5 fixed sub-stages, in this fixed order, never reordered or made variable-length: Discovery & Research, Define, Ideate & Wireframe, Design & Prototype, Test & Iterate.
- Each sub-stage: a numbered `Label` eyebrow (e.g. "01 — Discovery & Research", uppercase, tracked, muted-foreground) directly above a `Body` paragraph (1–2 sentences, per the template's own authoring guidance) — reuses the Hero's existing eyebrow+statement pairing rather than repeating `Heading` five times.
- 3 of the 5 sub-stages additionally render an `ImagePlaceholder` (`size="stage"`) directly below their paragraph, per the authoritative template's own image slots: Discovery & Research, Ideate & Wireframe, Design & Prototype.
- Sub-stages stack vertically with `gap-xl` (32px) between them. No horizontal stepper/timeline UI is introduced — out of scope, not required by any locked decision.

### Copy Tone Guidance for Placeholder Content (D-01)

- **Voice:** the same measured, plain-spoken register already established in `Homepage Copy V2.md`/`hero.ts` — no marketing hyperbole, no invented superlatives.
- **Boundary:** generic enough to describe a plausible UX process and role for the stated industry, without inventing quantified outcomes or claims attributed as fact to the real named client (Mashreq, Tata Capital, CAD, Verzion, Astrosure, AdReport).
- **Outcome & Impact bullets:** qualitative phrasing only (e.g. "Stakeholders approved the redesigned flow for the next release cycle", "Reduced the number of steps in the primary task flow") — never a specific invented number/percentage presented as a verified real result (do not write "reduced drop-off by 40%" as fact).
- **Challenge bullets:** plausible, industry-appropriate generic pain points (e.g. FinTech onboarding friction, dashboard information overload) — never client-specific fabricated detail.
- **Pull-quote (template marks this "Optional"):** omit for all 6 placeholder files this phase rather than inventing a fabricated stakeholder quote attributed to a real company — this is the single highest fabrication-risk element in the template, and the template's own annotation makes omission a legitimate, non-D-11-violating choice (see UI Considerations, row 9).
- **Learnings & Reflections:** should genuinely read as reflective ("what I'd do differently") even in placeholder form — the template explicitly asks this section to feel honest, so placeholder copy should model that register, not skip it as boilerplate.
