<objective>
Build the content loader: `import.meta.glob`-based file discovery wired to Plan 02-03's `parseCaseStudyFile`, with per-file failure isolation (one malformed `.md` file must never take down the other 5), deterministic `order`-field-based sorting, slug lookup, and circular "next case study" computation for the footer link. Per D-06, discovery uses Vite's native glob import rather than any Node-only build step, keeping the site fully static.

Purpose: This is CASE-04's "content-only change" guarantee made real -- the loader contains zero hardcoded slug literals, discovers files purely via a static glob pattern, and is the single data API every rendering component in Plan 02-09 depends on. It is also the one place in this phase where Plan 02-03's threat model explicitly deferred responsibility for isolating per-file parse/validation failures. `getCaseStudyBySlug` must also correctly return `undefined` (never throw) for any of the 5 deferred slugs D-10 excludes from this phase's content files, since those slugs remain real, navigable-in-principle Information Architecture entries that simply have no `.md` file backing them yet.
Output: `loader.ts` exporting `caseStudies: CaseStudy[]`, `getCaseStudyBySlug(slug)`, `getNextCaseStudy(currentSlug)`, and the pure, independently-testable `loadCaseStudiesFromRawFiles(rawFiles)` helper.
</objective>
