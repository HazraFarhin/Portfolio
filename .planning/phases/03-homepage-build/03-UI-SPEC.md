# Phase 3 — UI Design Contract

> Visual and interaction contract for the single-scroll homepage build. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — custom hand-rolled design system, not shadcn |
| Preset | not applicable |
| Component library | none — reuse `src/components/ui/{Button,Card,Typography}.tsx` (Phase 1) and `src/components/case-study/ImagePlaceholder.tsx` (Phase 2) verbatim; **zero new UI primitives** this phase |

**shadcn gate note:** `components.json` is absent; stack is React + Vite. Skipped deliberately — same rationale as Phase 2's UI-SPEC: Phase 1 already built a complete, Axisform-styled bespoke primitive set that every locked decision in `03-CONTEXT.md` requires reusing (RESEARCH.md's own recommendation: "every technical building block ... already exists"). Introducing shadcn now would contradict two phases of established pattern for zero benefit — this phase adds no new component primitives, only new content-driven compositions of the existing three.

## Typography

Already declared in `src/index.css` `@theme` (Phase 1) — **reused exactly as-is, no new size or weight added this phase**:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 (normal) | 1.4 |
| Body | 18px | 400 (normal) | 1.6 |
| Heading | 40px | 800 (extrabold) | 1.15 |
| Display | clamp(48px, 8vw, 88px) | 800 (extrabold) | 1.0 |

**Homepage-specific mapping (locked this phase):**

| Element | Component | `as` | Rationale |
|---------|-----------|------|-----------|
| Nav wordmark ("Hazra Farhin") | `Label` | `span`/`Link` | Small, quiet identity mark — a nav bar is chrome, not a content moment; must not compete with section headings |
| Section labels ("In Practice", "What I Do", "Field Archive", "How I Work", "Selected Work", "Skills", "About", "Brief") | `Label` | `p`/`span` | Reuses the exact eyebrow pattern already established by `heroContent.eyebrow` |
| Section headings ("Design, In Numbers", "Interfaces Built to Hold Up", "The Loop", etc.) | `Heading` | `h2` | One `Heading` per new section — consistent with Phase 2's case-study section-title convention; repeated at 40px deliberately, never diluted |
| Proof Strip stat numbers (~4, 8+, 3, 30%) | `Heading` (accent-colored override, see Color) | `p` | Large, punchy figures — reuses the existing 40px/extrabold weight rather than introducing a 5th size; color override (not size) creates the visual distinction |
| Proof Strip stat captions (years/industries/regions/reduction) | `Label` | `p` | Matches existing Label styling |
| How I Work's 6 action-words (listen / align / reduce / design. / prototype / systemize) | `Heading` | `span` | Reuses 40px extrabold rather than inventing an oversized "Display-scale" treatment — Display stays reserved for Hero (see note below) |
| Card body copy (Operating Stack's 5 cards, How I Work's Loop 5-step descriptions, About bio, Field Archive captions, footer tagline) | `Body` | `p` | Standard body reading copy |
| Tool chips (Skills & Tools), nav links, footer column links, "Coming soon" tag on deferred cards | `Label` | `span`/`a` | Small, quiet, uppercase-tracked — consistent chip/link register throughout |
| **Display** | *(not used this phase)* | — | Display remains reserved for the Hero (per 02-UI-SPEC.md). The existing Hero statement correctly uses `Body` (it is long-form prose, not a short headline) and this phase does not redesign Hero's typography beyond repointing `ctaHref` (Pitfall 1) — introducing Display elsewhere this phase would dilute its reserved status. |

No 5th font size and no 3rd font weight are introduced anywhere in this phase's UI.

## Color

Already declared in `src/index.css` `@theme` (Phase 1) — reused as-is, with one new, deliberate accent application:

| Role | Value | Usage this phase |
|------|-------|-------------------|
| Dominant (60%) | `#0B0C0A` | Page background, all sections |
| Secondary (30%) | `#16171A` | `Card` backgrounds (Operating Stack cards, Selected Work cards, deferred "coming soon" cards, About headshot placeholder), nav bar background (`bg-dominant/80` blended over page scroll — see Layout) |
| Accent (10%) | `#FF6A33` | Reserved for: **(1)** every `Button variant="primary"` CTA's border/hover state — Hero CTA (existing), Résumé download, Contact form's "Send the Brief →" submit button, and the "See more" toggle when in its expand state; **(2)** Proof Strip's 4 stat numbers (new this phase — the single new accent application, replacing `text-foreground` with `text-accent` on the `Heading`-styled figures only, never on their captions); **(3)** `focus-visible` outlines (existing, app-wide). **Never** used for section headings, body prose, nav links, footer links, or tool chips. |
| Destructive | `#E5484D` | Reserved for destructive actions only — **unused in this phase** (no destructive actions exist on the homepage); documented for completeness only |

Supporting tokens reused as-is: `--color-foreground` (#F2EFE6, body/heading text), `--color-muted-foreground` (labels, captions, muted nav links), `--color-line` (borders on `Card`/nav bar/`ImagePlaceholder`/tool chips).

**Discipline rule for this phase:** Nav links, footer column links, social/external links (LinkedIn, Behance, Website), and the deferred-slug "coming soon" cards' CTA must all use `Button variant="ghost"` (neutral line border) — **not** `variant="primary"`. With 5 sections each carrying their own heading + multiple links/chips, letting every clickable element carry accent would blow well past the 10% budget; only the CTAs and stat numbers listed above are accent-colored.

## Homepage Layout & Composition

**Section order (locked this phase, per RESEARCH.md's architecture diagram):**

1. **Nav** (persistent, fixed-position overlay, not part of scroll flow — `home.tsx`-scoped only, per D-06 clarified; does **not** render on `/case-study/:slug`)
2. `<section id="hero">` — existing (Phase 1), unchanged except `ctaHref` repoint
3. `<section id="proof-strip">` — new, HOME-02
4. `<section id="selected-work">` — new, HOME-03/HOME-04
5. `<section id="field-archive">` — new, D-04 (placed after Selected Work, before How I Work — bridges "the work" to "the process behind it")
6. `<section id="how-i-work">` — new, HOME-05 (Studio Method action-words + Operating Loop, per D-02)
7. `<section id="skills-tools">` — new, HOME-06
8. `<section id="about">` — new, HOME-07
9. `<section id="contact-footer">` — new, HOME-08/CONT-04 (Contact/Brief form UI + Footer, combined into one closing section per D-07)

**Section rhythm:** `py-2xl` (48px) between sections on desktop, `py-xl` (32px) on mobile — spacing tokens only, no new values (matches Phase 2's established rhythm).

### Nav Bar

- Fixed/sticky at top (`fixed inset-x-0 top-0 z-50`), `h-16`, `bg-dominant/80 backdrop-blur-lg border-b border-line` — a translucent glass bar consistent with the Card's own glass treatment, distinct from a solid opaque header.
- Content: wordmark (`Label`, "Hazra Farhin", links to `#hero`) on the left; 4 nav links (`Work`, `Method`, `Skills`, `Contact`, each `Label`-styled, plain `href="#id"`) on the right, collapsing to a simple horizontal row on mobile (no hamburger menu required — 4 links fit at all breakpoints without one).
- Nav links use plain `#id` anchors (not React Router `Link`) — consistent with `heroContent.ctaHref`'s existing precedent and D-06 clarified (homepage-only scope).

### Selected Work ("Work") — HOME-03/HOME-04

- One grid (`grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-lg`), never two separate grids.
- Initial render: the 6 real case studies from `caseStudies` (Phase 2 loader), each a `Card` showing title, client, summary (truncated to ~2 lines via CSS line-clamp — see UI Considerations), and cover-image `ImagePlaceholder` (`size="stage"` or `"banner"` — pick one consistently for all 6 cards, do not mix sizes within the grid).
- "See more" (`Button variant="ghost"`, centered below the grid) toggles local state, appending the 5 deferred cards into the **same** grid (D-09) — not a separate section/list.
- Deferred cards visually match the real 6's card shape (same `Card` component, same `ImagePlaceholder` treatment) but carry the `Coming soon` `Label` tag (Copywriting Contract) and link to `/case-study/<slug>` (the new coming-soon route, D-10) instead of the real case-study route.
- Toggle button label swaps `See more` ↔ `See less` on click; when expanded, the button remains present (does not disappear) so the user can collapse back — per D-09's "or disappears" allowance, this phase locks the **persistent toggle** behavior for a clearer, more predictable interaction.

### Field Archive

- Native `overflow-x-auto` horizontal scroller (`flex gap-md`, CSS `scroll-snap-type: x proximity`, `snap-x`) — **never** a `pin: true`/`ScrollTrigger.containerAnimation` scroll-jacked gallery (RESEARCH.md Pattern 4/Pitfall 2 — explicit anti-pattern per REQUIREMENTS.md).
- Accessibility: `role="region"`, `aria-label="Field Archive gallery"`, `tabIndex={0}` on the scroll container so keyboard users can focus and arrow/tab through it.
- The section's own entrance reveal (fade/rise on scroll into view) uses the existing `useScrollReveal(ref)` hook — decorative only, never scroll-position-linked horizontal motion.
- 6 caption cards (per Homepage Copy V2.md §06), each an `ImagePlaceholder` (`size="stage"`) with its caption beneath, `shrink-0 snap-start`.

### How I Work ("Method")

- Two content beats in one section (D-02, not two sections): (1) the 6 action-words (listen/align/reduce/design./prototype/systemize) as a `Heading`-styled typographic row/wrap (`flex flex-wrap gap-md`, not a numbered list); (2) the 5-step Operating Loop (Understand→Align→Structure→Design→Transfer), each step a `Label` (numbered eyebrow, e.g. "01 — Understand") + `Body` description, stacked with `gap-xl` — reuses the exact Process sub-stage pattern from Phase 2's case-study template (numbered eyebrow + paragraph, no new visual pattern invented).

### Skills & Tools

- 5 Operating Stack cards (`Card`, `grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-lg` or a 5-up row on wide desktop) — title (`Heading` or bold `Label`) + `Body` description per card, per D-03's 5 named capability areas.
- Tool chips row beneath the cards: `flex flex-wrap gap-sm`, each chip a small `Label`-styled pill (`rounded-full border border-line px-md py-xs`) — sourced via `[...new Set(caseStudies.flatMap((cs) => cs.tags))].sort()` (per D-14 clarified: frontmatter `tags` field only, alphabetically sorted for a stable, non-Set-iteration-order-dependent display: `AI Interface, Banking, Cloud, Dashboard, Design System, Enterprise, InsurTech, Mobile, UI, UX`).

### About

- Two-column layout on desktop (headshot placeholder left/right, bio right/left), stacking to single-column on mobile.
- Headshot: `ImagePlaceholder` at a **new** size token, `size="portrait"` (aspect `3/4`, `max-h-[320px]`) — a small, additive, backward-compatible extension to `ImagePlaceholderSize` (`'banner' | 'stage' | 'centerpiece' | 'portrait'`), per RESEARCH.md Pitfall 5 option (b); do not build a separate one-off placeholder component for this.
- Bio: `Body`, 2–4 sentences (D-12), no `Heading` needed beyond the section's own `Label` + `Heading` title (e.g. "About").

### Contact/Footer (combined closing section)

- **Contact/Brief block (top):** section label `Brief` (`Label`), intro copy (`Body`), then the static 3-field form (`What are you working on?`, `Reach me at, Email *`, `What needs to become clearer?`) — plain `<input>`/`<textarea>` elements styled consistent with the existing design system (line borders, dominant/secondary backgrounds, no new form-primitive component needed beyond native elements + `Label`), submit button `Send the Brief →` (`Button variant="primary"`, no `onClick`/handler this phase per D-07).
- **Footer block (bottom):** wordmark + tagline (`Body`), 3 columns (Contact / Elsewhere / Legal) per D-16's content, bottom copyright line. Résumé download CTA (`Download Résumé`) placed in the footer per HOME-08, not buried in a column — a `Button variant="primary"` at a visually prominent position (e.g. top of the footer block or beside the wordmark).

### Coming-Soon Route (`routes/coming-soon.tsx`, new)

- Composes only existing primitives (`Body` + `Button`), centered on the page — mirrors Phase 2's not-found fallback visual pattern exactly (same "quiet, centered, one CTA back" composition), no new component introduced.
- Distinct copy from both `not-found.tsx` (generic 404) and `CaseStudyPage`'s own "Case study not found" fallback (Phase 2) — see Copywriting Contract.
